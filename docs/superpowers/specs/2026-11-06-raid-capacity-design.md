# Exact theoretical RAID capacity

User scope: improve RAID capacity grading/explicit units, preserve equivalent correct answers, unrelated grading, module IDs and progress. The adopted autonomous workflow delegates ordinary pedagogical decisions and routine design gates; this is a bounded implementation, not a new storage simulator.

Decision: the existing RAID exercise computes theoretical usable capacity of equal-size disks before filesystem/metadata/formatting overhead, without hot spares. State decimal units explicitly: 1 GB = 10^9 bytes; 1 TB = 1000 GB = 10^12 bytes. Grade exactly after unit normalization: 4 TB and 4000 GB are equivalent; 3.9 TB, 4096 GB and nonzero fractional-byte deviations are not. Accept decimal comma/point, signs and exponent notation under the existing complete-number grammar; reject malformed/grouped numbers, unsupported units, unsafe ranges and non-integral byte values. No approximate answer policy is appropriate for this deterministic arithmetic.

Approaches: global tolerance removal would alter measurements/estimates; exact text would reject valid unit conversions; floating-point equality can alias near-equal decimal inputs. Choose a RAID-only field metadata rule with bounded decimal-to-safe-integer-byte parsing. Existing generated capacities are multiples of 250 GB and at most 64 TB, below the safe-integer byte limit. Do not change money parsing, RAID formulas, guaranteed-failure answers, visualization semantics, other conversion tolerances or historic records.

Implementation: add `decimalStorageBytes` to existing numericRule metadata; only the generated RAID usableCapacity field opts in. Add `parseDecimalStorageBytes(raw, unit)` for GB/TB; shared validator compares exact byte integers for tagged fields. Question and solution explain assumptions, units and exact grading; README/changelog reflect the shipped change. No dependencies/schema/backend/account changes.

Checks: literal 4 TB/4000 GB equivalence and wrong neighbors; comma/exponents/trailing zeros; missing/unsupported/prototype units, malformed/huge/sub-byte inputs; generated levels/sizes and both units; unrelated conversion/money rules; accessible field names, keyboard submit, wrong-to-next/correct/reveal and progress wiring using synthetic mocks; full tests, lint, types, build and desktop/narrow Chromium. Independent review before every push, Ready PR and real 15-minute review windows. Live persistence is separate and cannot be inferred from local tests.
